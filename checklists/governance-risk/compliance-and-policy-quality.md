# Checklist de Qualidade de Compliance e Políticas (Compliance & Policy Quality)

## Propósito
Garantir que todas as políticas organizacionais estejam atualizadas, que a trilha de
auditoria (audit trail) esteja completa e que exceções sejam documentadas formalmente.
Este checklist protege a organização contra riscos regulatórios, legais e reputacionais
decorrentes de políticas desatualizadas ou mal aplicadas.

## Quando Aplicar
- Na revisão anual obrigatória de políticas organizacionais
- Quando uma nova regulamentação entra em vigor e afeta a operação
- Após incidentes de compliance ou audit findings
- Antes de auditorias externas (financeira, regulatória, certificações)
- Quando uma exceção de política é solicitada ou concedida

## Agente Responsável
- **Primário:** Chief Compliance Officer (CCO) ou Head of Legal/Compliance
- **Secundário:** Cada Squad Lead para compliance dentro do seu domínio
- **Revisor:** CEO e Board para políticas de alto impacto

## Checklist

### Seção 1 — Políticas Vigentes (Current Policies)
- [ ] Item 1: O inventário completo de políticas ativas está atualizado e acessível
- [ ] Item 2: Cada política tem um owner designado responsável por manutenção
- [ ] Item 3: Cada política tem data de última revisão e data da próxima revisão programada
- [ ] Item 4: Nenhuma política está com revisão atrasada (overdue review)
- [ ] Item 5: Políticas estão escritas em linguagem clara e compreensível (não apenas legalês)
- [ ] Item 6: Políticas estão versionadas com histórico de mudanças rastreável
- [ ] Item 7: O repositório central de políticas está organizado e searchable
- [ ] Item 8: Novas políticas passam por processo formal de aprovação antes de entrar em vigor
- [ ] Item 9: Políticas obsoletas são arquivadas formalmente (não apenas deletadas)
- [ ] Item 10: Existe processo de comunicação para mudanças em políticas

### Seção 2 — Audit Trail (Trilha de Auditoria)
- [ ] Item 11: Todas as ações de compliance relevantes estão logadas com timestamp
- [ ] Item 12: O audit trail é imutável (não pode ser alterado retroativamente)
- [ ] Item 13: O período de retenção de registros atende aos requisitos regulatórios
- [ ] Item 14: Acessos ao audit trail estão controlados e logados (quem viu o quê)
- [ ] Item 15: O audit trail está integrado com sistemas críticos (financeiro, RH, operações)
- [ ] Item 16: Testes periódicos de integridade do audit trail são realizados
- [ ] Item 17: Backup do audit trail é realizado com frequência adequada
- [ ] Item 18: O audit trail está preparado para review por auditores externos

### Seção 3 — Exceções Documentadas (Documented Exceptions)
- [ ] Item 19: Toda exceção de política tem registro formal com justificativa
- [ ] Item 20: O aprovador da exceção está identificado e tem autoridade para aprovar
- [ ] Item 21: O período de validade da exceção está definido (não é permanente por default)
- [ ] Item 22: Controles compensatórios (compensating controls) estão definidos para cada exceção
- [ ] Item 23: Exceções são revisadas periodicamente para avaliar se ainda são necessárias
- [ ] Item 24: O volume de exceções é monitorado como indicador de saúde de políticas
- [ ] Item 25: Exceções frequentes no mesmo policy indicam necessidade de revisão da política

### Seção 4 — Treinamento e Awareness
- [ ] Item 26: Treinamento de compliance é obrigatório para todos os colaboradores
- [ ] Item 27: O calendário de treinamentos está definido e sendo cumprido
- [ ] Item 28: Novos colaboradores recebem treinamento de compliance no onboarding
- [ ] Item 29: Treinamentos específicos por função existem para áreas de alto risco
- [ ] Item 30: Taxas de conclusão de treinamento são monitoradas (target: >95%)
- [ ] Item 31: Avaliações de conhecimento pós-treinamento são aplicadas
- [ ] Item 32: Materiais de awareness estão atualizados e acessíveis

### Seção 5 — Monitoramento e Reporting
- [ ] Item 33: KPIs de compliance estão definidos e sendo trackeados (compliance scorecard)
- [ ] Item 34: Relatórios de compliance são gerados com frequência mínima trimestral
- [ ] Item 35: Incidentes de compliance são reportados e investigados em tempo hábil
- [ ] Item 36: Canal de denúncias (whistleblower channel) existe e é funcional
- [ ] Item 37: O canal de denúncias garante anonimato e proteção contra retaliação
- [ ] Item 38: Findings de auditorias anteriores foram endereçados com action plans
- [ ] Item 39: O status de remediação de findings é monitorado até o fechamento
- [ ] Item 40: Relatório de compliance é apresentado ao Board com frequência mínima semestral

### Seção 6 — Regulamentações Aplicáveis
- [ ] Item 41: O mapeamento de regulamentações aplicáveis está completo e atualizado
- [ ] Item 42: Mudanças regulatórias são monitoradas continuamente (regulatory radar)
- [ ] Item 43: O impacto de novas regulamentações é avaliado dentro de 30 dias da publicação
- [ ] Item 44: Existe processo formal para adaptar políticas a novas regulamentações
- [ ] Item 45: Assessoria jurídica externa é consultada para regulamentações complexas

## Critérios de Aprovação
O estado de compliance e políticas é considerado satisfatório quando:

1. **100% das políticas estão dentro do prazo de revisão (Seção 1)**
2. **Audit trail está completo e íntegro (Seção 2) — verificado por teste**
3. **Todas as exceções ativas estão documentadas e aprovadas (Seção 3)**
4. **Taxa de conclusão de treinamento está acima de 95% (Seção 4)**
5. **Todos os findings de auditoria estão com remediação em andamento ou concluída (Seção 5)**
6. **Mapeamento regulatório está atualizado (Seção 6)**
7. **O CCO assina o relatório de compliance como satisfatório**

## O que Fazer se Falhar
Se compliance e políticas não atingem os critérios:

1. **Risk assessment imediato:** Avaliar exposição legal e regulatória dos gaps identificados
2. **Priorização por risco:** Endereçar primeiro os gaps com maior impacto regulatório
3. **Task force:** Montar time dedicado para remediação se gaps são extensos
4. **Comunicação ao Board:** Informar o Board sobre gaps significativos de compliance
5. **Assessoria externa:** Contratar consultoria especializada se o gap é de conhecimento
6. **Freeze de exceções:** Suspender novas exceções até que o baseline esteja corrigido
7. **Plano de 30-60-90:** Criar plano de remediação com milestones claros
8. **Monitoramento reforçado:** Aumentar frequência de reporting até a normalização
