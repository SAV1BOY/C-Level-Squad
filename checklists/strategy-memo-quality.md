# Checklist de Qualidade — Strategy Memo

## Propósito
Assegurar que todo strategy memo articule com clareza a tese estratégica, defina a arena de atuação, explicite as escolhas feitas (e as rejeitadas), documente os trade-offs, identifique as capabilities necessárias e vincule um plano de execução concreto. Este checklist é o quality gate para qualquer documento estratégico de médio ou longo prazo.

## Quando Aplicar
- Na criação ou revisão de estratégia corporativa, de produto ou de unidade de negócio.
- Antes de apresentação ao board ou comitê executivo.
- Em ciclos de planejamento anual ou semestral.
- Quando um pivot estratégico está sendo considerado.
- Sempre que um agente gerar um draft estratégico para validação humana.

## Agente Responsável
- **Primário:** CEO Agent
- **Revisor:** Strategy Advisor Agent, CFO Agent
- **Validador Final:** CEO humano ou board

## Checklist

### Tese Estratégica
- [ ] A tese central está articulada em no máximo 2 parágrafos
- [ ] A tese responde claramente "por que vamos vencer?"
- [ ] O insight diferenciado que sustenta a tese está explícito
- [ ] A tese é falsificável — existem condições que a invalidariam
- [ ] Os pressupostos críticos estão listados e numerados
- [ ] A tese foi testada contra evidências contrárias (steel-man do argumento oposto)
- [ ] O horizonte temporal da tese está definido (1 ano, 3 anos, 5 anos)
- [ ] A tese está conectada à missão e visão da organização

### Arena Definida
- [ ] O mercado-alvo está definido com clareza (segmento, geografia, perfil)
- [ ] O TAM/SAM/SOM está estimado com fontes referenciadas
- [ ] Os competidores principais estão mapeados com posicionamento relativo
- [ ] As dinâmicas de mercado relevantes estão descritas (crescimento, consolidação, disrupção)
- [ ] Os clientes-alvo estão definidos com personas ou segmentos específicos
- [ ] As arenas onde NÃO vamos competir estão explicitamente listadas
- [ ] O timing de entrada ou expansão está justificado
- [ ] Os canais de distribuição estão identificados

### Escolhas Explícitas
- [ ] As 3-5 escolhas estratégicas principais estão listadas e priorizadas
- [ ] Cada escolha tem uma justificativa clara vinculada à tese
- [ ] As escolhas rejeitadas estão documentadas com razões
- [ ] O framework de priorização utilizado está declarado
- [ ] As escolhas de "onde jogar" vs "como vencer" estão separadas
- [ ] Os trade-offs entre escolhas estão articulados
- [ ] O grau de convicção em cada escolha está declarado
- [ ] As escolhas são internamente consistentes (não se contradizem)

### Trade-offs Documentados
- [ ] Os trade-offs estratégicos estão listados em formato explícito
- [ ] O que estamos sacrificando está tão claro quanto o que estamos priorizando
- [ ] Os trade-offs de curto prazo vs longo prazo estão articulados
- [ ] O impacto financeiro dos trade-offs está estimado
- [ ] Os trade-offs foram comunicados aos stakeholders relevantes
- [ ] Existe clareza sobre o que NÃO faremos como consequência das escolhas
- [ ] Os trade-offs de velocidade vs qualidade estão explícitos
- [ ] Os trade-offs de crescimento vs rentabilidade estão quantificados

### Capabilities Identificadas
- [ ] As capabilities necessárias para executar a estratégia estão listadas
- [ ] O gap entre capabilities atuais e necessárias está mapeado
- [ ] O plano para fechar cada gap está definido (build, buy, partner)
- [ ] O timeline para desenvolvimento de capabilities está estimado
- [ ] O investimento necessário em cada capability está quantificado
- [ ] As capabilities que são vantagem competitiva sustentável estão destacadas
- [ ] Os talentos-chave necessários estão identificados
- [ ] As capabilities tecnológicas (AI, data, infra) estão detalhadas
- [ ] Os riscos de execução por capability estão avaliados

### Plano de Execução Vinculado
- [ ] O plano de execução está referenciado com link ou documento anexo
- [ ] Os OKRs derivados da estratégia estão definidos
- [ ] Os milestones trimestrais estão especificados
- [ ] Os owners de cada iniciativa estratégica estão nomeados
- [ ] O budget alocado por iniciativa está detalhado
- [ ] Os kill criteria para cada aposta estratégica estão definidos
- [ ] O mecanismo de revisão e ajuste está programado (cadência)
- [ ] As dependências entre iniciativas estão mapeadas
- [ ] O plano de comunicação da estratégia está definido

### Coerência e Formatação
- [ ] O documento segue a estrutura "Playing to Win" ou framework equivalente
- [ ] A narrativa é coerente do início ao fim — sem contradições internas
- [ ] Os dados e análises de suporte estão em anexos referenciados
- [ ] O documento principal tem no máximo 5-7 páginas
- [ ] A linguagem é acessível a todos os stakeholders-alvo
- [ ] O version control está aplicado
- [ ] A data de próxima revisão está agendada

## Critérios de Aprovação
- A tese estratégica deve ser clara e falsificável.
- Pelo menos 3 escolhas estratégicas devem estar articuladas com trade-offs.
- Todas as capabilities críticas devem ter plano de fechamento de gap.
- O plano de execução deve estar vinculado com OKRs e owners.
- O documento deve ter sido revisado por pelo menos 2 membros do C-Level.

## O que Fazer se Falhar
1. Identificar as seções incompletas e devolver ao autor com feedback específico.
2. Agendar sessão de trabalho (working session) para preencher gaps críticos.
3. Se a tese for fraca, realizar sessão de stress-test com red team.
4. Não apresentar ao board até que todos os critérios estejam atendidos.
5. Registrar gaps recorrentes no RalphLoop para calibração de processo.
