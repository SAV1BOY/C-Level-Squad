# COO Cross-Functional Alignment

## Propósito
Garantir que as dependências entre áreas funcionais estão mapeadas, compreendidas e alinhadas. Desalinhamento cross-functional é uma das maiores fontes de atrito, atraso e desperdício organizacional. Cada interface entre áreas é um ponto potencial de falha que precisa ser gerido ativamente.

## Quando Aplicar
- Mensalmente como parte da revisão operacional
- Quando projetos cross-functional estiverem atrasados por falha de coordenação
- Quando houver conflitos recorrentes entre áreas sobre prioridades ou recursos
- Após reorganizações que mudem interfaces entre áreas
- No início de projetos que envolvam mais de 2 áreas funcionais

## Agente Responsável
**Agente COO (Chief Operating Officer Agent)** — responsável por garantir alinhamento e coordenação eficaz entre todas as áreas funcionais da organização.

## Checklist

### Seção 1: Mapeamento de Dependências
- [ ] Mapa de dependências cross-functional existe e está atualizado
- [ ] Todas as interfaces críticas entre áreas estão identificadas
- [ ] O tipo de dependência está classificado: blocking, informacional, colaborativa
- [ ] Dependências blocking têm SLAs definidos para resolução
- [ ] Dependências cíclicas (A depende de B que depende de A) estão identificadas
- [ ] O impacto de cada dependência no delivery é quantificado
- [ ] Dependências de terceiros que afetam múltiplas áreas estão mapeadas
- [ ] O mapa é revisado pelo menos mensalmente com representantes de cada área

### Seção 2: Alinhamento de Prioridades
- [ ] Cada área conhece as top 3 prioridades das áreas com as quais tem dependência
- [ ] Conflitos de prioridade entre áreas estão identificados e resolvidos
- [ ] Existe um mecanismo de arbitragem para conflitos de prioridade (escalation path)
- [ ] OKRs cross-functional existem para iniciativas que envolvem múltiplas áreas
- [ ] Roadmaps de diferentes áreas foram sincronizados para evitar conflitos
- [ ] Recursos compartilhados têm alocação acordada e visível
- [ ] Não há "guerras de prioridade" não resolvidas há mais de 1 semana
- [ ] O C-Level arbitra conflitos de prioridade em até 48 horas quando escalados

### Seção 3: Mecanismos de Coordenação
- [ ] Existem rituais de sync entre áreas com dependências críticas
- [ ] A frequência de sync é proporcional à intensidade da dependência
- [ ] Canais de comunicação entre áreas estão definidos e eficazes
- [ ] Handoffs entre áreas têm processo definido e verificável
- [ ] Não há informação crítica que "se perde" entre áreas
- [ ] Ferramentas de projeto permitem visibilidade cross-functional
- [ ] Existe um ponto de contato (liaison) designado para cada interface crítica
- [ ] Mecanismos de coordenação são proporcionais — nem excesso nem falta

### Seção 4: Resolução de Conflitos
- [ ] Processo de resolução de conflitos cross-functional está definido
- [ ] Conflitos são tratados no nível mais baixo possível antes de escalar
- [ ] Escalação é vista como ferramenta legítima, não como falha
- [ ] Conflitos resolvidos têm decisão documentada e comunicada
- [ ] Padrões de conflito recorrente são analisados para tratamento na raiz
- [ ] Não há "guerras frias" — conflitos não resolvidos que viram ressentimento
- [ ] Retrospectivas cross-functional são realizadas após projetos conjuntos
- [ ] A cultura valoriza colaboração entre áreas, não silos e territorialismo

### Seção 5: Métricas e Melhoria
- [ ] Lead time de requests cross-functional é medido e rastreado
- [ ] Satisfação entre áreas é medida periodicamente (internal NPS)
- [ ] Número de projetos cross-functional concluídos no prazo é rastreado
- [ ] Custo de desalinhamento é estimado (retrabalho, atrasos, oportunidades perdidas)
- [ ] Melhores práticas de colaboração cross-functional são documentadas e compartilhadas
- [ ] Times com melhor colaboração são reconhecidos como exemplo
- [ ] O overhead de coordenação é monitorado para não crescer desproporcionalmente
- [ ] Feedback de melhoria é coletado e implementado a cada ciclo

## Critérios de Aprovação
- Mapa de dependências atualizado e validado por todas as áreas
- Zero conflitos de prioridade não resolvidos há mais de 1 semana
- SLAs de interfaces blocking com taxa de cumprimento acima de 85%
- Mecanismos de coordenação ativos para todas as interfaces críticas
- Pelo menos 85% dos itens de todas as seções concluídos
- Internal NPS entre áreas acima do threshold definido

## O que Fazer se Falhar
1. Identificar as interfaces com maior atrito e tratar como prioridade
2. Realizar sessão de alinhamento entre líderes das áreas em conflito
3. Implementar OKRs compartilhados para forçar alinhamento em objetivos comuns
4. Designar liaisons dedicados para interfaces que não funcionam
5. Considerar reorganização se conflitos forem estruturais e recorrentes
6. Implementar retrospectivas cross-functional obrigatórias após projetos conjuntos
7. Escalar para CEO se conflitos persistirem após intervenção do COO
8. Re-auditar em 30 dias com foco nas interfaces mais problemáticas
