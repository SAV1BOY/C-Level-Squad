# Accountability System Audit

## Propósito
Verificar que o sistema de accountability da organização está funcionando: RACI/DRI definidos para todas as áreas críticas, SLAs internos estabelecidos e cumpridos, e padrões de performance são claros e aplicados. Sem accountability, execução é opcional.

## Quando Aplicar
- Mensalmente como parte da revisão operacional
- Quando houver recorrência de tarefas sem dono ou com múltiplos donos
- Quando SLAs internos estiverem sendo sistematicamente descumpridos
- Após reorganizações de time ou mudanças de estrutura
- Quando houver conflitos recorrentes sobre responsabilidades entre áreas

## Agente Responsável
**Agente COO (Chief Operating Officer Agent)** — responsável por definir, manter e auditar o sistema de accountability organizacional.

## Checklist

### Seção 1: RACI/DRI Framework
- [ ] Matriz RACI existe e está atualizada para todos os processos críticos
- [ ] Cada processo crítico tem um DRI (Directly Responsible Individual) designado
- [ ] O DRI tem autoridade compatível com sua responsabilidade
- [ ] Não há processos com múltiplos "Responsible" sem um "Accountable" claro
- [ ] A matriz RACI está acessível e conhecida por todos os envolvidos
- [ ] Mudanças na RACI são versionadas e comunicadas formalmente
- [ ] Novos projetos/processos recebem RACI antes de iniciar execução
- [ ] A RACI é revisada trimestralmente para refletir mudanças organizacionais
- [ ] Não há "zonas cinzentas" — áreas onde ninguém é claramente responsável
- [ ] Conflitos de RACI são escalados e resolvidos dentro de 48 horas

### Seção 2: SLAs Internos
- [ ] SLAs internos entre áreas estão definidos e documentados
- [ ] Cada SLA tem métricas mensuráveis e thresholds claros
- [ ] SLAs são monitorados com frequência adequada (diária, semanal, mensal)
- [ ] Breach de SLA gera alerta automático ou notificação formal
- [ ] Existe processo de escalação quando SLAs são descumpridos
- [ ] SLAs são revisados semestralmente para ajuste de realidade
- [ ] O cumprimento de SLAs é visível para todas as partes envolvidas
- [ ] SLAs críticos (que impactam cliente final) têm prioridade máxima

### Seção 3: Padrões de Performance
- [ ] Cada função/papel tem critérios de performance claros e documentados
- [ ] Expectativas de entrega são comunicadas no início de cada ciclo
- [ ] Performance é avaliada com base em dados, não apenas percepção
- [ ] Feedback é dado com frequência adequada (não apenas em annual review)
- [ ] High performers são reconhecidos e recompensados visivelmente
- [ ] Low performers recebem feedback direto e plano de melhoria com prazo
- [ ] O padrão de "bom o suficiente" está definido (não é ambíguo)
- [ ] Existe distinção clara entre falha de execução e falha de processo

### Seção 4: Sistema de Tracking e Visibilidade
- [ ] Existe um sistema único para tracking de compromissos e entregas
- [ ] Status de cada compromisso é atualizado pelo menos semanalmente
- [ ] Dashboards de accountability são acessíveis a toda liderança
- [ ] Atrasos são visíveis antes do deadline (early warning system)
- [ ] O sistema diferencia: no prazo, em risco, atrasado, concluído
- [ ] Histórico de performance por time/indivíduo é mantido
- [ ] O sistema é simples o suficiente para ser usado consistentemente
- [ ] Overhead de manutenção do sistema é proporcional ao valor gerado

### Seção 5: Cultura de Accountability
- [ ] A liderança pratica accountability visível (lead by example)
- [ ] Erros são tratados como aprendizado, não como punição (exceto recorrência)
- [ ] Compromissos são feitos publicamente e cobrados publicamente
- [ ] "Eu não sabia" e "ninguém me disse" não são aceitos como justificativa
- [ ] Existe distinção cultural entre "tentou e falhou" e "não tentou"
- [ ] Times se cobram mutuamente, não apenas de cima para baixo
- [ ] O sistema de accountability é percebido como justo e consistente
- [ ] Accountability é celebrada como valor, não como burocracia

## Critérios de Aprovação
- RACI atualizada para 100% dos processos críticos com DRIs designados
- SLAs internos definidos para todas as interfaces entre áreas
- Taxa de cumprimento de SLAs acima de 85%
- Sistema de tracking ativo e utilizado por toda liderança
- Pelo menos 85% dos itens de todas as seções concluídos
- Nenhuma "zona cinzenta" de responsabilidade ativa

## O que Fazer se Falhar
1. Mapear imediatamente as zonas cinzentas e designar DRIs
2. Para SLAs descumpridos: root cause analysis em até 5 dias
3. Implementar daily standup para áreas com accountability baixa
4. Realizar workshop de RACI com líderes das áreas afetadas
5. Considerar ajuste de estrutura organizacional se conflitos forem estruturais
6. Implementar consequence management para descumprimento recorrente
7. Simplificar ferramentas e processos se overhead for a causa da falha
8. Re-auditar em 30 dias com foco nos itens críticos que falharam
