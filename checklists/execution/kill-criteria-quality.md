# Checklist de Qualidade de Kill Criteria (Kill Criteria Quality)

## Propósito
Garantir que toda iniciativa, projeto ou investimento tenha critérios de encerramento
(kill criteria) definidos antes do início, com thresholds claros e um plano de
documentação para o encerramento. Este checklist combate a inércia organizacional
que mantém projetos vivos por sunk cost fallacy, política ou ausência de critérios
objetivos de parada.

## Quando Aplicar
- No kick-off de toda iniciativa estratégica ou investimento significativo
- Em cada gate review de projetos (verificar se kill criteria foram atingidos)
- Na revisão trimestral de portfólio de iniciativas
- Quando um projeto mostra sinais persistentes de underperformance
- Ao redesenhar o framework de governança de projetos

## Agente Responsável
- **Primário:** Project Owner ou Initiative Sponsor
- **Secundário:** CFO para critérios financeiros e Chief of Staff para processo
- **Revisor:** Investment Committee ou C-Level Squad como corpo decisório

## Checklist

### Seção 1 — Definição de Kill Criteria (Criteria Definition)
- [ ] Item 1: Kill criteria foram definidos antes do início da iniciativa (não depois)
- [ ] Item 2: Os critérios são quantitativos e mensuráveis (não subjetivos)
- [ ] Item 3: Pelo menos 3 dimensões de kill criteria estão definidas (financeira, temporal, qualitativa)
- [ ] Item 4: Thresholds numéricos para cada critério estão especificados (ex: "se churn > 15%")
- [ ] Item 5: O período de observação para cada critério está definido (avaliar por quanto tempo)
- [ ] Item 6: A distinção entre warning threshold (yellow) e kill threshold (red) está clara
- [ ] Item 7: Critérios são realistas e atingíveis de serem medidos com dados disponíveis
- [ ] Item 8: Kill criteria foram acordados pelo sponsor e pelo owner da iniciativa
- [ ] Item 9: Kill criteria estão documentados no charter do projeto ou business case
- [ ] Item 10: Os critérios foram revisados pelo CFO para consistência financeira

### Seção 2 — Tipos de Kill Criteria
- [ ] Item 11: Critério financeiro de kill está definido (ex: ROI negativo após X meses)
- [ ] Item 12: Critério de prazo está definido (ex: milestone Y não atingido até data Z)
- [ ] Item 13: Critério de mercado está definido (ex: product-market fit score abaixo de threshold)
- [ ] Item 14: Critério de adoção está definido (ex: menos de X% de adoption rate após launch)
- [ ] Item 15: Critério de custo está definido (ex: budget excedido em mais de 30%)
- [ ] Item 16: Critério de oportunidade está definido (ex: se surgir alternativa superior)
- [ ] Item 17: Critério estratégico está definido (ex: desalinhamento com nova estratégia)
- [ ] Item 18: A combinação de critérios para trigger kill está clara (qualquer um ou combinação)

### Seção 3 — Monitoramento de Kill Criteria
- [ ] Item 19: Métricas de kill criteria são monitoradas com frequência definida (semanal ou mensal)
- [ ] Item 20: O responsável por monitorar cada critério está designado
- [ ] Item 21: Dashboard ou report que mostra proximidade dos kill thresholds existe
- [ ] Item 22: Alertas são gerados quando métricas se aproximam do warning threshold
- [ ] Item 23: O monitoramento é independente do project owner (evitar auto-avaliação enviesada)
- [ ] Item 24: O status dos kill criteria é incluído em cada status report do projeto
- [ ] Item 25: O CFO ou finance team valida dados financeiros dos kill criteria

### Seção 4 — Processo de Kill Decision
- [ ] Item 26: O fórum de decisão para kill está definido (quem decide: owner, committee, CEO)
- [ ] Item 27: O processo de trigger (como iniciar a discussão de kill) está documentado
- [ ] Item 28: O time envolvido no projeto é consultado antes da decisão (não surpreendido)
- [ ] Item 29: A análise de sunk cost vs. prospective value é conduzida formalmente
- [ ] Item 30: Alternativas ao kill completo são consideradas (pivot, scope reduction, pause)
- [ ] Item 31: O impacto do kill em pessoas, clientes e parceiros está avaliado
- [ ] Item 32: O timeline de wind-down está definido (não é um corte abrupto sem plano)
- [ ] Item 33: A comunicação interna e externa do kill está planejada
- [ ] Item 34: A decisão de kill é documentada no decision log com rationale completo

### Seção 5 — Documentação e Aprendizado Pós-Kill
- [ ] Item 35: Um postmortem do projeto encerrado é conduzido dentro de 2 semanas
- [ ] Item 36: Aprendizados específicos estão documentados (o que funcionou e o que não)
- [ ] Item 37: A hipótese original do projeto é reavaliada à luz dos resultados
- [ ] Item 38: Ativos gerados pelo projeto (código, dados, insights) são preservados e catalogados
- [ ] Item 39: Pessoas do projeto são realocadas rapidamente e com respeito
- [ ] Item 40: Clientes ou usuários afetados são comunicados e compensados se aplicável
- [ ] Item 41: O kill é tratado culturalmente como boa gestão de recursos, não como fracasso
- [ ] Item 42: O portfolio de investimentos é atualizado para refletir o encerramento

### Seção 6 — Cultura de Kill Decision
- [ ] Item 43: A organização tem histórico de tomar kill decisions quando necessário
- [ ] Item 44: Líderes que recomendam kill não são penalizados na avaliação de performance
- [ ] Item 45: O CEO referencia kill decisions como exemplos de disciplina de capital
- [ ] Item 46: Cases de kill decisions bem-sucedidas são compartilhados como aprendizado
- [ ] Item 47: O processo de kill é revisado anualmente para melhorar efetividade
- [ ] Item 48: Sunk cost fallacy é tema de treinamento regular para lideranças

## Critérios de Aprovação
O framework de kill criteria é considerado adequado quando:

1. **100% das iniciativas ativas têm kill criteria definidos antes do início**
2. **Kill criteria são quantitativos para pelo menos 80% das iniciativas**
3. **Monitoramento está ativo e atualizado para todas as iniciativas (Seção 3)**
4. **Kill decisions são tomadas dentro de 30 dias após atingir thresholds**
5. **Postmortems de projetos encerrados são conduzidos (Seção 5)**
6. **A cultura não penaliza kill decisions honestas (Seção 6)**
7. **O Investment Committee revisou os kill criteria no último trimestre**

## O que Fazer se Falhar
Se o framework de kill criteria não está funcionando:

1. **Kill criteria retrofit:** Para projetos que não têm, definir kill criteria retroativamente
2. **Portfolio review forçado:** CFO lidera revisão de todos os projetos contra kill criteria
3. **Zombie hunt:** Identificar projetos que deveriam ter sido encerrados mas continuam
4. **Incentive alignment:** Garantir que a estrutura de incentivos não penaliza kills
5. **CEO mandate:** CEO deve comunicar que kill decisions são esperadas e celebradas
6. **Process training:** Treinar líderes no framework de kill criteria e decision-making
7. **Quick kills:** Encerrar imediatamente projetos que claramente atingiram kill criteria
8. **Capital reallocation:** Redirecionar capital liberado para oportunidades de maior impacto
