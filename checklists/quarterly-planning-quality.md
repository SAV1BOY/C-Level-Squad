# Checklist de Qualidade — Planejamento Trimestral (Q-Plan)

## Propósito
Assegurar que o planejamento trimestral contenha apostas definidas, recursos alocados, riscos identificados, milestones claros, owners designados e kill criteria explícitos. O Q-Plan é o documento operacional que traduz a estratégia anual em ação concreta para os próximos 90 dias, e este checklist garante que essa tradução seja rigorosa e acionável.

## Quando Aplicar
- No início de cada trimestre, durante o ciclo de planejamento
- Quando há replanejamento mid-quarter por mudança significativa de contexto
- Antes de apresentar o Q-Plan ao board ou comitê executivo
- Na revisão de Q-Plans de squads e departamentos subordinados
- Quando o agente de planejamento gera um draft para validação humana

## Agente Responsável
- **Primário:** CoS Agent (Chief of Staff Agent)
- **Co-responsável:** CEO Agent e CFO Agent
- **Revisor:** Cada C-Level Agent para sua respectiva área
- **Facilitador:** Strategy Advisor Agent

## Checklist

### Seção 1 — Apostas Definidas (Bets)
- [ ] As 3-5 apostas principais do trimestre estão listadas e priorizadas por impacto
- [ ] Cada aposta tem uma tese clara — por que acreditamos que isso vai funcionar
- [ ] O vínculo entre cada aposta e a estratégia anual está explícito e documentado
- [ ] Cada aposta tem um outcome esperado mensurável (não apenas output)
- [ ] As apostas descartadas estão registradas com justificativa para não inclusão
- [ ] O nível de confiança (conviction level) em cada aposta está declarado
- [ ] As apostas estão categorizadas: core (70%), adjacent (20%), transformacional (10%)
- [ ] As interdependências entre apostas estão mapeadas explicitamente
- [ ] Cada aposta tem uma narrativa de sucesso descrevendo o estado desejado ao final do Q

### Seção 2 — Recursos Alocados
- [ ] O budget total do trimestre está definido e aprovado pelo CFO Agent
- [ ] A alocação de budget por aposta está detalhada e totaliza o budget aprovado
- [ ] O headcount necessário por aposta está identificado (existente e a contratar)
- [ ] Os gaps de capacidade estão mapeados com plano de fechamento (hire, contract, redeploy)
- [ ] A alocação de tempo dos líderes está explícita (% de foco por aposta)
- [ ] Os recursos compartilhados (infraestrutura, plataformas, equipes de suporte) estão reservados
- [ ] O custo de oportunidade da alocação escolhida está documentado
- [ ] Existe buffer de recursos para contingências (mínimo 10-15%)
- [ ] A alocação está validada contra o capacity planning real das equipes

### Seção 3 — Riscos Identificados
- [ ] Os riscos de execução de cada aposta estão listados e categorizados
- [ ] Cada risco tem probabilidade e impacto estimados (matriz de risco)
- [ ] Os riscos de dependência entre equipes estão especificamente chamados
- [ ] Riscos de mercado ou externos relevantes para o trimestre estão documentados
- [ ] Riscos de capacidade (pessoas insuficientes, skills ausentes) estão avaliados
- [ ] Riscos regulatórios ou de compliance para o período estão identificados
- [ ] Os planos de mitigação para riscos de alta severidade estão definidos
- [ ] Early warning signals estão identificados para cada risco material
- [ ] O owner de cada risco está designado explicitamente

### Seção 4 — Milestones
- [ ] Cada aposta tem milestones mensais (mínimo 3 por aposta no trimestre)
- [ ] Cada milestone tem uma data específica e um deliverable verificável
- [ ] Os milestones estão sequenciados respeitando dependências entre equipes
- [ ] Milestones intermediários permitem validação incremental (não apenas entrega final)
- [ ] O caminho crítico (critical path) está identificado e destacado
- [ ] As datas dos milestones são realistas considerando feriados, vacações e sazonalidade
- [ ] Os milestones estão integrados ao dashboard de acompanhamento do squad
- [ ] Check-ins semanais estão agendados para tracking de progresso dos milestones

### Seção 5 — Owners Designados
- [ ] Cada aposta tem exatamente um owner accountable (pessoa ou agente nomeado)
- [ ] Cada milestone tem um responsible designado (pode ser diferente do owner da aposta)
- [ ] Os owners aceitaram explicitamente a responsabilidade (não foram atribuídos sem consulta)
- [ ] Os owners têm autoridade e recursos suficientes para entregar
- [ ] A RACI matrix para iniciativas cross-functional está definida
- [ ] O mecanismo de accountability está claro (cadência de reviews, formato de reporting)
- [ ] O escalation path está documentado para cada owner
- [ ] Backups estão identificados para owners de iniciativas críticas

### Seção 6 — Kill Criteria
- [ ] Cada aposta tem kill criteria explícitos e mensuráveis
- [ ] O threshold de performance mínima para continuar a aposta está definido
- [ ] O momento de avaliação (evaluation checkpoint) está agendado no calendário
- [ ] O processo de decisão de kill está documentado (quem decide, com base em quê)
- [ ] Os sunk costs foram reconhecidos para não influenciar a decisão de kill
- [ ] O plano de realocação de recursos pós-kill está delineado
- [ ] O impacto de kill em outras apostas dependentes está mapeado
- [ ] A comunicação de kill está planejada (quem informa, como, quando)
- [ ] Existe compromisso explícito de honrar os kill criteria (sem mover goalposts)

### Seção 7 — Coerência e Formatação
- [ ] O Q-Plan está alinhado com o Annual Operating Plan (AOP) vigente
- [ ] As métricas do Q-Plan são consistentes com os OKRs do período
- [ ] O documento segue o template padrão e está acessível no repositório oficial
- [ ] O Q-Plan foi revisado por pelo menos 2 membros do C-Level Squad
- [ ] O version control está aplicado e o histórico de mudanças está preservado
- [ ] O Q-Plan anterior foi retrospectivado e as lições incorporadas

## Critérios de Aprovação
- Todas as apostas têm owner, budget, milestones e kill criteria definidos
- Os riscos de alta severidade têm plano de mitigação e owner designado
- A alocação de recursos totaliza corretamente e está validada pelo CFO Agent
- O Q-Plan está alinhado com a estratégia anual e os OKRs vigentes
- Pelo menos 2 revisores do C-Level validaram o documento
- Score mínimo de completude: 90% dos itens do checklist marcados

## O que Fazer se Falhar
1. Identificar as seções com gaps e devolver ao owner com feedback específico
2. Priorizar correção de kill criteria e riscos — são as seções mais frequentemente incompletas
3. Se o problema for de alocação de recursos, convocar sessão de trade-off com CFO Agent
4. Se as apostas não estiverem claras, realizar sessão de clarificação com CEO Agent
5. Definir prazo de 72 horas para correção antes do início do trimestre
6. Registrar padrões de falha no RalphLoop para melhoria do processo
7. Não iniciar execução com Q-Plan que não passou pelo quality gate
