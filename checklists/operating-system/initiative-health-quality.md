# Checklist de Saúde de Iniciativas (Initiative Health Quality)

## Propósito
Fornecer uma avaliação rápida e padronizada da saúde de cada iniciativa estratégica
em andamento. Este checklist permite ao C-Level Squad identificar rapidamente quais
iniciativas precisam de atenção, quais blockers existem e quais decisões precisam
ser tomadas para destravar progresso.

## Quando Aplicar
- Semanalmente em cada check-in de iniciativa dentro do squad
- Nas revisões quinzenais de portfólio do C-Level Squad
- Quando um stakeholder solicita status atualizado de uma iniciativa
- Ao preparar reports para board ou investidores
- Quando há mudança significativa de contexto que afeta iniciativas em andamento

## Agente Responsável
- **Primário:** Initiative Owner (responsável direto pela iniciativa)
- **Secundário:** Chief of Staff para consolidação e dashboard de portfólio
- **Revisor:** Sponsor executivo da iniciativa

## Checklist

### Seção 1 — Status Geral (Traffic Light Assessment)
- [ ] Item 1: A iniciativa tem um traffic light status atualizado (green, yellow, red)
- [ ] Item 2: O traffic light reflete a realidade, não otimismo do owner (honesty check)
- [ ] Item 3: O critério para cada cor está padronizado e documentado
- [ ] Item 4: Se yellow ou red, o motivo específico está descrito em uma frase
- [ ] Item 5: A tendência (melhorando, estável, piorando) está indicada junto ao traffic light
- [ ] Item 6: O status foi atualizado nos últimos 7 dias (freshness check)
- [ ] Item 7: O owner da iniciativa assinou pessoalmente o status reportado

### Seção 2 — Progresso e Milestones
- [ ] Item 8: O percentual de conclusão está estimado com base em milestones, não em tempo decorrido
- [ ] Item 9: O próximo milestone está identificado com data esperada de conclusão
- [ ] Item 10: Milestones concluídos no período estão listados como evidência de progresso
- [ ] Item 11: Milestones atrasados estão sinalizados com nova data estimada e razão do atraso
- [ ] Item 12: O confidence level de atingir o próximo milestone está indicado (alto, médio, baixo)
- [ ] Item 13: O velocity do time está sendo medido e está estável ou melhorando
- [ ] Item 14: Se o projeto está ahead of schedule, riscos de qualidade foram verificados

### Seção 3 — Blockers e Impedimentos (Blockers Identification)
- [ ] Item 15: Todos os blockers atuais estão listados com descrição clara
- [ ] Item 16: Cada blocker tem um owner responsável pela resolução
- [ ] Item 17: Cada blocker tem uma data estimada de resolução
- [ ] Item 18: Blockers que dependem de decisão executiva estão escalados
- [ ] Item 19: Blockers que persistem há mais de 2 semanas estão sinalizados como críticos
- [ ] Item 20: O impacto de cada blocker no timeline geral está quantificado
- [ ] Item 21: Workarounds temporários estão implementados onde possível
- [ ] Item 22: Blockers resolvidos no período estão documentados com resolução aplicada

### Seção 4 — Decisões Necessárias (Decisions Needed)
- [ ] Item 23: Decisões pendentes que afetam a iniciativa estão listadas explicitamente
- [ ] Item 24: Para cada decisão, o decision-maker está identificado
- [ ] Item 25: Para cada decisão, as opções com prós e contras estão documentadas
- [ ] Item 26: O deadline para cada decisão está definido (quando a falta de decisão vira blocker)
- [ ] Item 27: Decisões tomadas no período estão registradas no decision log
- [ ] Item 28: O impacto de não-decisão (decision debt) está quantificado onde relevante
- [ ] Item 29: Decisões reversíveis vs. irreversíveis estão classificadas (Type 1 vs. Type 2)

### Seção 5 — Riscos Ativos (Active Risks)
- [ ] Item 30: Os top 3 riscos ativos da iniciativa estão listados
- [ ] Item 31: Cada risco tem probabilidade e impacto atualizados
- [ ] Item 32: Novos riscos identificados no período estão documentados
- [ ] Item 33: Riscos que se materializaram estão sendo tratados com plano de ação
- [ ] Item 34: O risk register da iniciativa está sincronizado com o risk register do portfólio

### Seção 6 — Recursos e Budget (Resources & Budget)
- [ ] Item 35: O burn rate financeiro está dentro do orçado (variação < 10%)
- [ ] Item 36: A utilização de headcount está conforme planejado
- [ ] Item 37: Se há necessidade de recursos adicionais, o pedido está formalizado
- [ ] Item 38: Forecast de custos até conclusão está atualizado
- [ ] Item 39: ROI ou impacto esperado ainda justifica o investimento (viability check)

### Seção 7 — Dependências (Dependencies)
- [ ] Item 40: Dependências de outros squads estão atualizadas e confirmadas
- [ ] Item 41: Dependências externas (vendors, partners) estão no prazo
- [ ] Item 42: Novas dependências identificadas foram comunicadas aos squads afetados
- [ ] Item 43: SLAs de dependências cross-squad estão sendo cumpridos
- [ ] Item 44: Plano B existe para dependências de alto risco

### Seção 8 — Comunicação e Alinhamento
- [ ] Item 45: O stakeholder map está atualizado com nível de engajamento de cada um
- [ ] Item 46: Comunicação regular com stakeholders está acontecendo conforme cadência definida
- [ ] Item 47: Mudanças de escopo, timeline ou budget foram comunicadas a todos os afetados
- [ ] Item 48: O time da iniciativa está alinhado sobre prioridades e next steps

## Critérios de Aprovação
A saúde da iniciativa é considerada adequada quando:

1. **Mínimo de 80% dos itens aplicáveis estão completos**
2. **O traffic light (Seção 1) está atualizado e foi validado pelo sponsor**
3. **Todos os blockers (Seção 3) têm owner e data estimada de resolução**
4. **Decisões pendentes (Seção 4) estão escaladas para os decision-makers corretos**
5. **O burn rate financeiro está dentro da variação aceitável (Seção 6)**
6. **Dependências cross-squad (Seção 7) estão confirmadas e no prazo**
7. **O status foi atualizado nos últimos 7 dias**

## O que Fazer se Falhar
Se a saúde da iniciativa não atinge os critérios:

1. **Escalação imediata:** Sponsor deve ser notificado em até 24 horas
2. **War room:** Se a iniciativa é Tier 1, convocar war room com stakeholders-chave
3. **Blocker blitz:** Sessão dedicada para resolver blockers acumulados
4. **Decision forcing:** Escalar decisões pendentes com deadline de 48 horas
5. **Resource injection:** Se o problema é de capacidade, solicitar reforço temporário
6. **Scope cut:** Negociar redução de escopo para proteger timeline e qualidade essenciais
7. **Pause and reset:** Se a iniciativa está em red por mais de 3 semanas, considerar pausa
8. **Kill criteria review:** Verificar se os kill criteria da iniciativa foram atingidos
