# Checklist de Qualidade do Protocolo de Escalação (Escalation Protocol Quality)

## Propósito
Garantir que o caminho de escalação entre e dentro de squads esteja claramente
definido, com tempos de resposta estabelecidos e processos testados. Este checklist
evita que problemas fiquem presos em loops sem resolução, que escalações demorem
demais ou que cheguem à pessoa errada, causando atrasos e frustração.

## Quando Aplicar
- Na revisão trimestral do operating system cross-squad
- Após incidentes onde a escalação falhou ou demorou demais
- Quando novos squads ou funções são criados
- Ao onboardar novas lideranças que precisam entender o processo de escalação
- Quando feedback indica insatisfação com a velocidade de resolução de problemas

## Agente Responsável
- **Primário:** Chief of Staff como designer e guardião do protocolo de escalação
- **Secundário:** Cada Squad Lead para escalações dentro e a partir do seu squad
- **Revisor:** CEO como último nível de escalação e validador do protocolo

## Checklist

### Seção 1 — Definição do Protocolo (Protocol Definition)
- [ ] Item 1: O protocolo de escalação está documentado e acessível a toda liderança
- [ ] Item 2: Os níveis de escalação estão definidos (Level 1: squad lead, Level 2: C-Level, Level 3: CEO)
- [ ] Item 3: Cada nível de escalação tem critérios claros de quando ativar
- [ ] Item 4: O protocolo distingue entre escalação técnica e escalação de decisão
- [ ] Item 5: O processo para iniciar uma escalação está descrito passo a passo
- [ ] Item 6: O formato de informação necessária para escalar está padronizado (template)
- [ ] Item 7: O protocolo cobre escalação dentro do squad e entre squads
- [ ] Item 8: Escalação de emergência (fora de horário, fins de semana) está prevista
- [ ] Item 9: O protocolo foi revisado e atualizado nos últimos 6 meses
- [ ] Item 10: Exemplos de escalações reais bem-sucedidas estão documentados como referência

### Seção 2 — Tempos de Resposta (Response Time SLAs)
- [ ] Item 11: SLA de acknowledgment (confirmar recebimento) está definido por nível de severidade
- [ ] Item 12: Para escalações P0 (críticas), acknowledgment deve ser em até 30 minutos
- [ ] Item 13: Para escalações P1 (altas), acknowledgment deve ser em até 2 horas
- [ ] Item 14: Para escalações P2 (médias), acknowledgment deve ser em até 24 horas
- [ ] Item 15: SLA de resolução está definido por nível de severidade
- [ ] Item 16: Para P0, resolução ou plano de resolução em até 4 horas
- [ ] Item 17: Para P1, resolução ou plano de resolução em até 48 horas
- [ ] Item 18: Para P2, resolução em até 1 semana
- [ ] Item 19: Compliance com SLAs de escalação é medida e reportada mensalmente
- [ ] Item 20: Se um SLA é violado, a escalação automaticamente sobe para o próximo nível

### Seção 3 — Cadeia de Escalação (Escalation Chain)
- [ ] Item 21: Para cada tipo de problema (técnico, financeiro, people, estratégico), a cadeia está definida
- [ ] Item 22: Cada nível da cadeia tem um nome e backup designados (não apenas "o squad lead")
- [ ] Item 23: Informações de contato para escalação estão atualizadas e testadas
- [ ] Item 24: A cadeia de escalação está disponível em formato simples (one-pager visual)
- [ ] Item 25: A cadeia contempla ausências (férias, licenças) com substitutos claros
- [ ] Item 26: Não existe gap na cadeia (todos os tipos de problema têm caminho definido)
- [ ] Item 27: O CEO está acessível como último nível de escalação quando necessário
- [ ] Item 28: Escalações cross-squad têm um ponto de convergência (Chief of Staff)

### Seção 4 — Qualidade da Escalação
- [ ] Item 29: Escalações incluem contexto suficiente para o próximo nível agir (não são vagas)
- [ ] Item 30: O impacto do problema está quantificado na escalação (financeiro, clientes, timeline)
- [ ] Item 31: Ações já tentadas estão documentadas (o que foi feito antes de escalar)
- [ ] Item 32: A decisão ou ação necessária está claramente articulada (o que se espera do escalado)
- [ ] Item 33: O deadline para resolução está indicado (quando se torna irreversível)
- [ ] Item 34: Escalações frívolas (que poderiam ser resolvidas no nível atual) são identificadas e desencorajadas
- [ ] Item 35: Escalações tardias (que deveriam ter sido feitas antes) são identificadas e corrigidas

### Seção 5 — Resolução e Follow-Up
- [ ] Item 36: Toda escalação é rastreada desde a abertura até a resolução completa
- [ ] Item 37: O status de escalações ativas é visível para ambas as partes (escalador e resolvedor)
- [ ] Item 38: Uma vez resolvida, a escalação é formalmente fechada com documentação
- [ ] Item 39: Root cause da necessidade de escalação é analisada (poderia ter sido evitada?)
- [ ] Item 40: Ações preventivas são definidas para evitar recorrência do mesmo tipo de escalação
- [ ] Item 41: Métricas de escalação (volume, tempo de resolução, recorrência) são reportadas
- [ ] Item 42: Escalações recorrentes no mesmo tema geram revisão de processo ou ownership

### Seção 6 — Treinamento e Cultura de Escalação
- [ ] Item 43: Todos os squad leads são treinados no protocolo de escalação
- [ ] Item 44: A cultura incentiva escalação precoce para problemas graves (não há estigma)
- [ ] Item 45: A cultura desencorage escalação como transferência de responsabilidade
- [ ] Item 46: Novos líderes recebem treinamento de escalação na primeira semana
- [ ] Item 47: Simulações de escalação (drills) são conduzidas pelo menos semestralmente
- [ ] Item 48: O CEO reforça que escalar cedo e com qualidade é sinal de maturidade

## Critérios de Aprovação
O protocolo de escalação é considerado funcional quando:

1. **O protocolo está documentado e atualizado nos últimos 6 meses (Seção 1)**
2. **SLAs de resposta estão definidos e compliance está acima de 90% (Seção 2)**
3. **A cadeia de escalação está completa, sem gaps, com backups (Seção 3)**
4. **85% das escalações incluem contexto suficiente para ação (Seção 4)**
5. **100% das escalações são rastreadas até resolução (Seção 5)**
6. **Treinamento de escalação está completo para 100% dos squad leads (Seção 6)**
7. **O Chief of Staff validou o protocolo no último trimestre**

## O que Fazer se Falhar
Se o protocolo de escalação não está funcionando:

1. **Protocol review:** Chief of Staff lidera revisão completa do protocolo
2. **Training blitz:** Treinar ou retreinar todos os squad leads em 2 semanas
3. **Template enforcement:** Garantir que o template de escalação é usado em 100% dos casos
4. **SLA monitoring:** Implementar monitoramento automático de SLAs se não existe
5. **Drills:** Conduzir simulação de escalação para testar o processo na prática
6. **Feedback collection:** Coletar feedback de quem escala e de quem recebe escalações
7. **Simplification:** Se o protocolo é complexo demais, simplificar para os cenários mais comuns
8. **CEO reinforcement:** CEO comunica importância do protocolo em reunião de liderança
