# IT Governance — Peter Weill & Jeanne Ross (2004)

## Resumo Executivo

Weill e Ross demonstram que empresas com IT governance eficaz geram retornos sobre IT
20% superiores a seus peers. O livro define IT governance como o framework de direitos
de decisão e accountability para incentivar comportamento desejável no uso de IT.
Não é sobre que decisões de IT tomar, mas sobre QUEM toma cada tipo de decisão.

A tese: IT governance não é burocracia — é clareza de direitos de decisão que permite
velocidade com alinhamento. Empresas sem governance não são ágeis — são caóticas.

## Conceitos-Chave

### IT Governance Defined
- Framework de direitos de decisão e accountability que incentiva comportamento desejável
- Não é sobre tecnologia — é sobre quem decide e como se responsabiliza
- Top performers: decisões claras, transparentes e consistentes
- Governance ≠ management: governance decide QUEM decide; management toma as decisões

### Five Key IT Decisions
1. **IT Principles**: Papel de IT no negócio (declarações de alto nível)
2. **IT Architecture**: Organização lógica de dados, aplicações e infraestrutura
3. **IT Infrastructure**: Shared services e capacidades técnicas centralizadas
4. **Business Application Needs**: Requisitos de negócio para aplicações compradas ou built
5. **IT Investment & Prioritization**: Quanto e onde investir em IT

### Governance Archetypes (Quem Decide)
- **Business Monarchy**: C-level de negócio decide (sem IT na mesa)
- **IT Monarchy**: IT decide unilateralmente
- **Feudal**: Cada BU decide para si mesma
- **Federal**: Combinação de central e local (mais comum em top performers)
- **IT Duopoly**: IT e uma ou mais BUs decidem juntos
- **Anarchy**: Cada indivíduo/pequeno grupo decide — caos

### Governance Mechanisms
**Decision-Making Structures:**
- Committees (IT steering committee, architecture review board)
- Executive roles (CIO, CTO, CDO) com autoridade definida
- Process-specific roles (data owners, architecture owners)

**Alignment Processes:**
- Investment approval process
- Architecture exception process
- Service level agreements
- Chargeback/showback mechanisms

**Communication Approaches:**
- IT principles publicados e comunicados
- Web-based portals com policies e standards
- Office of CIO communication
- Senior management announcements

### Governance Performance
- Empresas com governance eficaz: +20% ROI em IT
- Governance eficaz correlaciona com: clareza de direitos de decisão, transparência,
  comunicação ativa
- Ineficaz: decisões ad hoc, conflitos de autoridade, shadow IT proliferando

### IT Governance Design Framework
1. Que comportamento desejável queremos incentivar?
2. Quais são as 5 decisões-chave?
3. Quem tem input vs. quem tem decision rights para cada?
4. Que mecanismos (estruturas, processos, comunicação) implementam as decisões?
5. Como medimos se a governance está funcionando?

## Frameworks e Modelos

### IT Governance Matrix
| Decisão | Input Rights | Decision Rights | Archetype |
|---------|-------------|----------------|-----------|
| IT Principles | C-Level + IT | C-Level | Business Monarchy |
| Architecture | IT + Key BUs | CTO/IT | IT Duopoly |
| Infrastructure | IT | CTO/IT | IT Monarchy |
| Business Apps | BU + IT | BU + IT | Federal |
| Investment | C-Level + IT | CFO + CIO | IT Duopoly |

### Governance Assessment
1. Para cada decisão-chave: quem decide REALMENTE (não formalmente)?
2. As decisões são consistentes entre si?
3. Os mecanismos (comitês, processos) funcionam na prática?
4. Shadow IT é indicador de governance gaps — onde está proliferando?
5. Stakeholders entendem seus direitos e responsabilidades?

## Aplicação ao C-Level Squad

### Para o CEO Agent
- IT governance é responsabilidade do C-Level, não apenas do CIO/CTO
- Definir IT principles como declaração de papel de IT no negócio
- Garantir que governance balance velocidade com alinhamento

### Para o CTO Agent
- Propor e implementar architecture governance (review boards, standards)
- Gerenciar o equilíbrio entre padronização (governance) e inovação (autonomia)
- Liderar infrastructure decisions com input das BUs

### Para o CFO Agent
- Co-liderar IT investment prioritization com CIO/CTO
- Implementar mecanismos de chargeback/showback para transparência de custos
- Governança de budget de IT como parte da governança financeira geral

### Para o CMO Agent
- Participar como input em business application needs para martech stack
- Respeitar architecture governance ao escolher ferramentas de marketing
- Evitar shadow IT em marketing — integrar com platform quando possível

### Para o COO Agent
- Participar de governance como owner de processos operacionais
- Garantir que IT decisions suportem eficiência operacional
- Operational SLAs como mecanismo de governance e accountability

## Takeaways Acionáveis (top 5)

1. **Defina quem decide** — Para cada uma das 5 decisões-chave, explicite quem tem input
   e quem tem decision rights. Ambiguidade é o inimigo da governance eficaz.

2. **Publique e comunique** — Governance que existe apenas em documentos não funciona.
   Publique princípios, processes e direitos de decisão ativamente.

3. **Monitore shadow IT** — Onde shadow IT prolifera, governance tem gaps. Não proíba —
   entenda a necessidade e ajuste governance ou ofereça alternativa melhor.

4. **Balance control com velocidade** — Governance excessiva paralisa; governance
   insuficiente gera caos. O sweet spot é clareza de decisão com delegação.

5. **Avalie regularmente** — Governance é dinâmica. Revise anualmente: as decisões estão
   sendo tomadas como definido? Os mecanismos funcionam? Os resultados melhoraram?
