# Framework: Jobs to Be Done (JTBD)

## Descrição

Jobs to Be Done é um framework de inovação desenvolvido por Clayton Christensen, Tony Ulwick e outros, que propõe que clientes não compram produtos — eles "contratam" produtos para realizar um "trabalho" (job) em suas vidas. O JTBD muda o foco da análise de quem é o cliente (demografia) para o que o cliente está tentando alcançar (job). Isso revela oportunidades de inovação que pesquisas tradicionais de mercado não capturam, porque pessoas frequentemente não sabem articular o que querem, mas sabem o que estão tentando fazer.

## Quando Usar

### Situações Ideais
- Definir ou redefinir proposição de valor do produto
- Entender por que clientes realmente compram (ou não compram)
- Identificar oportunidades de inovação em mercados maduros
- Segmentar mercado por necessidade, não por demografia
- Analisar competição de forma mais ampla (concorrentes inesperados)
- Priorizar features de produto com base em jobs não atendidos

### Quando NÃO Usar
- Otimização tática de curto prazo (usar testes A/B)
- Quando o job é óbvio e bem compreendido
- Para decisões que requerem dados quantitativos rápidos

## Como Aplicar

### Passo 1: Identificar o Job
```
Formato: "Quando [situação], eu quero [motivação], para que [resultado esperado]"

Exemplo: "Quando estou preso no trânsito pela manhã, eu quero me sentir
produtivo, para que não sinta que estou perdendo tempo."

Componentes do Job:
- Funcional: o que precisa ser feito objetivamente
- Emocional: como quer se sentir
- Social: como quer ser percebido
```

### Passo 2: Mapear o Job
```
Etapas do Job (Job Map):
1. Definir - O que preciso alcançar?
2. Localizar - Que inputs preciso?
3. Preparar - Como me organizo?
4. Confirmar - Estou pronto para fazer?
5. Executar - Fazer o trabalho
6. Monitorar - Está funcionando?
7. Modificar - Preciso ajustar?
8. Concluir - Finalizar e arrumar
```

### Passo 3: Avaliar Satisfação Atual
```
Para cada etapa do job e cada outcome desejado:
- Importância (1-5): quão importante é este outcome?
- Satisfação (1-5): quão bem a solução atual atende?

Oportunidade = Alta importância + Baixa satisfação
Formula (Ulwick): Opportunity Score = Importance + (Importance - Satisfaction)
Score > 12 = Alta oportunidade
Score 10-12 = Oportunidade moderada
Score < 10 = Bem atendido
```

### Passo 4: Gerar Soluções
```
Para oportunidades identificadas:
- Brainstorm soluções que atendam o job melhor
- Avaliar contra jobs emocionais e sociais, não apenas funcional
- Considerar soluções de diferentes categorias/indústrias
- Prototipar e testar com clientes no contexto do job
```

## Exemplos

### Exemplo Clássico: Milkshake McDonald's
```
Job: "Quando estou dirigindo para o trabalho de manhã, quero algo que me
mantenha entretido e satisfeito, para que a viagem passe rápido e eu não
sinta fome até o almoço."

Concorrentes inesperados: banana, donut, bagel, café
Solução: milkshake grosso (demora para consumir), portátil, satisfatório

Insight: O concorrente não era Burger King, era a banana.
```

### Exemplo SaaS B2B
```
Job: "Quando preciso tomar decisões estratégicas, quero ter dados confiáveis
e visualizáveis rapidamente, para que pareça informado nas reuniões e tome
decisões melhores."

Funcional: acessar dados, gerar relatórios
Emocional: sentir confiança nas decisões
Social: parecer informado e competente
Concorrentes: Excel, BI tools, consultoria, instinto
```

### Aplicação em Product Strategy
```
Job Map para "Recrutar engenheiro sênior":
1. Definir: qual perfil preciso?
2. Localizar: onde encontrar candidatos?
3. Preparar: criar JD, alinhar equipe
4. Confirmar: pipeline tem candidatos suficientes?
5. Executar: entrevistar e avaliar
6. Monitorar: candidato está engajado no processo?
7. Modificar: ajustar oferta se necessário
8. Concluir: onboarding efetivo

Oportunidade: etapas 2 e 6 são mal atendidas → inovação aqui
```

## Limitações

- **Subjetividade** - Identificar o "verdadeiro" job requer interpretação habilidosa
- **Retrospectivo** - Baseado em comportamento passado, pode não prever rupturas futuras
- **Complexidade** - Jobs podem ser hierárquicos e interdependentes, difícil simplificar
- **Execution gap** - Do insight do job à solução há um salto criativo não trivial
- **Duas escolas** - Christensen (qualitativo) vs. Ulwick (quantitativo) podem confundir
- **Escala** - Entrevistas JTBD são intensivas e difíceis de escalar
- **Cultural bias** - Jobs emocionais e sociais variam muito entre culturas
