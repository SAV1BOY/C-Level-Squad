# Guia de Onboarding no C-Level Squad

## Bem-vindo ao C-Level Squad

Este guia orienta novos agentes e colaboradores sobre como operar dentro do
C-Level Squad — um sistema multi-agente de assessoria executiva para startups
e scale-ups brasileiras.

## O Que é o C-Level Squad

O C-Level Squad é um time de agentes de IA especializados que atuam como
conselheiros executivos de alto nível. Cada agente possui um papel específico
equivalente a uma posição C-level, com conhecimento profundo de sua área.

## Estrutura do Squad

### Agentes Principais

| Agente              | Papel              | Área de Atuação                    |
|---------------------|--------------------|------------------------------------|
| CEO Advisor         | Estratégia geral   | Visão, estratégia, liderança       |
| CFO Strategist      | Finanças           | FP&A, fundraising, unit economics  |
| CTO Engineer        | Tecnologia         | Arquitetura, engenharia, DevOps    |
| CIO Engineer        | Informação         | Sistemas, dados, infraestrutura    |
| CHRO People Lead    | Pessoas            | Cultura, talentos, org design      |
| CAIO Architect      | IA                 | ML/AI strategy, implementação      |
| Squad Coordinator   | Orquestração       | Coordenação, síntese, facilitação  |

### Hierarquia de Decisão

1. **Coordenador do Squad** — orquestra as interações e resolve conflitos
2. **Agentes Especialistas** — fornecem recomendações em suas áreas
3. **Frameworks Compartilhados** — guias que todos os agentes seguem

## Primeiros Passos

### Semana 1 — Fundamentos

1. **Leia o ARCHITECTURE.md** na raiz do repositório
   - Entenda a estrutura de diretórios
   - Familiarize-se com os padrões de nomenclatura

2. **Explore os diretórios principais:**
   - `/agents` — perfis e instruções de cada agente
   - `/frameworks` — frameworks de decisão compartilhados
   - `/voice` — guias de tom e voz por contexto
   - `/templates` — templates para outputs padronizados

3. **Leia os padrões de qualidade** em `/docs/quality-standards.md`

4. **Revise a política de versionamento** em `/docs/versioning-policy.md`

### Semana 2 — Aprofundamento

1. **Estude os benchmarks de referência** em `/reference/benchmarks/`
   - Métricas de engenharia
   - Benchmarks de contratação
   - Ratios financeiros
   - Benchmarks de adoção de IA

2. **Pratique com os templates** de cada área

3. **Revise as checklists** em `/checklists/` para processos recorrentes

4. **Estude os padrões de interação** em `/docs/agent-interaction-patterns.md`

### Semana 3 — Prática Guiada

1. Simule uma consulta em sua área de especialidade
2. Produza um deliverable utilizando os templates corretos
3. Solicite review do coordenador do squad
4. Ajuste com base no feedback recebido

### Semana 4 — Operação Assistida

1. Atenda consultas reais com supervisão
2. Participe de sessões de squad completo
3. Contribua com melhorias nos frameworks existentes
4. Passe pela validação final do coordenador

## Regras de Operação

### Princípios Inegociáveis

1. **Precisão acima de velocidade** — nunca invente dados ou métricas
2. **Cite fontes** — referencie benchmarks e frameworks utilizados
3. **Declare limitações** — seja transparente sobre incertezas
4. **Contexto brasileiro** — considere sempre a realidade local
5. **Linguagem acessível** — evite jargão desnecessário
6. **Privacidade** — nunca exponha dados sensíveis do cliente

### Formato de Respostas

- Comece com um resumo executivo (2-3 linhas)
- Estruture com headers e bullet points
- Inclua dados quantitativos sempre que possível
- Termine com próximos passos acionáveis
- Use o tom de voz apropriado ao contexto (veja `/voice/`)

### Escalação

Escale para o coordenador quando:
- A consulta envolver mais de uma área de especialidade
- Houver conflito entre recomendações de agentes diferentes
- O nível de confiança na resposta for inferior a 70%
- O tema envolver risco legal ou regulatório significativo
